## 0. 先看一张全景图

```
接上冷备盘
   │
   ▼
【采集】─────────────────────────────► 快照（单文件"档案柜"）
   │                                        │
   │ 可选：磁盘体检信息                      ├─ 随时查询：概览 / 最大文件 / 目录占用 / 搜索
   │ 可选：文件指纹（内容校验）              ├─ 对比：新旧快照差异（含目录级汇总）
   │                                        └─ 报告：导出 HTML / 旧格式 CSV
```

这个工具只做两件事，**永远不搬数据**：

1. **采集**：给盘拍一张"档案照"——记录盘上有什么、什么信息（存成一个"快照"）。
2. **比对**：把两张档案照对照，告诉你多了什么、少了什么、什么变了。

## 1. 现在的问题，用大白话说

现在的版本已经能拍、能比，但实测在两块 TOSHIBA 盘上暴露出明显不足。其中一块盘的数据：**298 万个文件、5.2 万个目录、约 1.87TB**，采集结果是一本 **1.13GB 的大流水账**（纯文本 CSV）。

| 你可能真的会问 | 现在的结果 |
|---|---|
| "这盘里最大的 50 个文件是什么？" | 要把它当 1.13GB 的文本从头翻到尾，没有任何索引 |
| "写真合集"目录到底占了多少空间？ | 算不出来——记录里只有一个个文件，没有"目录"这一层 |
| "文件内容被悄悄改过吗？" | 看不出——只记录了大小和修改时间，同样的字节数看不出差别 |
| "这块盘还是原来那块盘吗？" | 不可靠——USB 硬盘盒会挡住真实硬盘的型号和序列号，现有记录记的经常是盒子的信息 |
| "采集到一半断电了，能接着采吗？" | 不能，只能推倒重来 |
| "上次采集跳过了哪些文件？" | 有记录，但同一条重复写了两遍，要手工处理 |
| "把文件清单给我一份稳定格式的表？" | 列结构会随路径深浅变化，表头不稳定，不方便和别的工具对接 |

一句话总结：**不是采集逻辑差，而是"拿一本流水账当数据库用"。**

## 2. 升级后的日常是什么样的

一个典型使用日（其实一年也就用几次）：

1. 接上盘，运行一条采集命令；
2. 等到结束（三百万文件的盘预计几十分钟），得到一个**单文件的"档案柜"**——不用装任何数据库软件，一个文件就能拷走、随盘冷存、独立校验；
3. 之后像查资料一样随便问它问题：

| 想做的事 | 升级后的用法（示意，正式命令名待定） |
|---|---|
| 接上新盘，采集 | `cm collect E:` |
| 整体概览（文件数、总大小、类型分布） | `cm stats 快照目录` |
| 最大的 50 个文件 | `cm top 50` |
| 每个目录占多少空间 | `cm du` |
| 按名字搜文件 | `cm find "发票"` |
| 和上次对比 | `cm diff 旧快照 新快照` |
| 生成一份报告 | `cm report 快照` |

**升级后，查看数据的方式会发生质变：从"翻流水账"变成"查档案柜"。**

## 3. 升级方向一：采集维度（记录什么）

总思路：**原来只记录文件，现在连目录、文件的多重身份、磁盘健康信息都能记，而且记录过程更省事。**

### 3.1 目录也记账了

- 现状：只有文件有记录，"空目录"才单独提到；普通目录完全不出现。
- 升级后：每个目录也是一条正式记录（带自己的修改时间）。
- 好处：
  - 能回答"每个目录占多少空间"；
  - 能看出"哪个目录最近动过东西"；
  - 对比时，"目录新增/消失"也能看见，不再只有文件级变化。
- 代价：多出几十万行记录，相对 300 万文件可以忽略。

### 3.2 每个文件多记几张"身份信息"

| 新增记录项 | 通俗解释 | 有什么好处 |
|---|---|---|
| 扩展名（.jpg/.mkv） | 文件的"种类标签" | "只看图片/只看视频"变成一条命令、秒出结果 |
| 创建时间 | 文件在这块盘上"出生"的时间 | 判断哪些资料是哪一批备份进去的 |
| 真实占用空间 | 按盘的最小分配单位算的实际占用，通常略大于文件大小 | 回答"空间到底去哪了"更准确 |
| 文件属性 | 隐藏、系统、只读这些标记 | 过滤规则能按属性真正生效 |

刻意**不记录**的：访问时间（噪音大、没信息量）、复杂的权限明细（绝大多数场景用不上）。少记无用信息，本身就是让工具更简单可靠。

### 3.3 磁盘的"体检信息"（可选）

- 新能力：如果电脑上装了免费工具 `smartmontools`，采集时顺手记录硬盘健康状态——温度、通电小时、坏道计数等。
- 为什么值得做：冷备盘的典型死法是"放着放着就不行了"；每年留一条体检记录，能提前发现苗头。
- 拿不到不算错：USB 硬盘盒经常读不到这些信息，属正常情况；记录下来即可，**绝不因为读不到而中断采集**。

### 3.4 认清"到底是哪块盘"

- 现状：记录的是 USB 盒子的信息（比如 JMicron），真盘被挡在后面；序列号也常常读不到。
- 升级后：优先记录真盘型号 + 序列号；同时记录"卷序列号"等换电脑、换盘符都不会变的标识。
- 好处：同一块盘的历次快照永远能对上号，不会张冠李戴。

### 3.5 文件指纹（哈希）——按需使用

先解释它是什么：**给文件内容算一串"指纹"**。内容变一个字节，指纹就完全不同。

- 为什么贵：要把盘上所有文件完整读一遍（几 TB 的机械盘大约几小时），这是物理下限，没有捷径。
- 什么时候用（做成独立命令，不绑在采集里）：
  - **平时采集：不算指纹**（零成本），只按大小 + 时间推测"可能变了没"；
  - **重要节点（盘寄回来、年度检查）：全量算一次指纹**，得到完整的内容校验；
  - **平时想做简单体检：抽样指纹**（比如随机抽 1% 加上所有大于 1GB 的文件），几分钟完成。
- 额外的大礼（有了指纹才能做）：
  - 识别**改名 / 搬家**——同一个指纹从一个路径挪到另一个路径，"一个删除 + 一个新增"会被配对成"这块文件只是换位置了"（整理过目录的盘特别常见）；
  - 找出**重复文件**。
- 省时机制：如果某个文件的大小和修改时间跟上次快照一样，指纹直接沿用上次的，不重复计算。

### 3.6 采集过程本身更省事

| 现在 | 升级后 |
|---|---|
| 每块盘从头到尾扫两遍 | 只扫一遍，采集时间约省三到五成 |
| 中途断电 = 重来 | 断了以后可以从断点接着采 |
| 排除规则写了但没生效 | 真正生效，且被排除的文件都会记账 |
| 跳过记录每条重复两遍 | 记录结构天然去重，只留一条 |
| 采完没有总结 | 采完打印摘要：文件数 / 目录数 / 跳过数 / 总大小 / 耗时 |

## 4. 升级方向二：查看维度（怎么用数据）

### 4.1 为什么要把存储换掉

现在的 1.13GB CSV，就像一本**没有目录的流水账**：想查任何东西都得从头翻。

升级后，每个快照存成一个 **SQLite 数据库文件**。可以把它理解成一个"单文件的档案柜"：

- 不用安装任何数据库软件（Python 自带）；
- 一个文件就能拷走、随盘冷存、单独校验；
- 查单个文件毫秒级，按目录统计秒级；
- 两个快照对比 = 两个柜子按目录对照，不用每次重新排序。

体积和现在的 CSV 差不多（约 1GB 级），但可用性完全不是一个量级。

### 4.2 能直接回答哪些问题

| 问题 | 升级后 | 目标速度（300 万文件） |
|---|---|---|
| 最大的 50 个文件 | 一条命令直接出表 | 1 秒内 |
| 每个目录占多少空间、逐层展开 | 一条命令 | 1–2 秒 |
| 找名字/路径里带某个词的文件 | 一条命令（内置全文索引） | 1 秒内 |
| 按时间、大小、扩展名筛选 | 一条命令 | 秒级 |
| 上次采集跳过了哪些文件 | 一条命令，已去重 | 毫秒级 |
| 新旧快照完整对比（含目录级汇总） | 一条命令 | 目标 1 分钟内 |

### 4.3 对比功能的具体升级

| 现在 | 升级后 |
|---|---|
| 只有文件级的增 / 删 / 改 | 增加**目录级汇总**："`/photos/2023` 下新增 412、删除 3、变更 1"，一眼看出变化集中在哪 |
| 目录变化完全不可见 | 目录是正式记录，新增/消失一目了然 |
| 改名 / 搬家 = 一个删除 + 一个新增 | 有指纹时识别为"改名 / 移动" |
| 结果只能存 CSV | 表格 / CSV / Markdown / HTML 报告任选 |
| 脚本无法判断"有没有差异" | 明确的返回码：无差异 = 0，有差异 = 1，出错 = 2，方便自动化 |
| 两次采集口径不同也可能直接比 | 比对前自动检查口径是否一致，不一致会提醒 |

### 4.4 报告

- `cm report` 一键生成**单文件 HTML 报告**：总览、空间分布、最大的文件、变更摘要、跳过清单，双击就能打开，可存档、可发送。
- 本地网页版界面列入后期可选项（不是当前必需）。

## 5. 旧数据怎么办

- **不用重采**：一条 `cm import-legacy` 命令，把旧的三个 CSV 装进新"档案柜"，之后就能用新工具查询、比对。
- **回得去**：需要旧格式时，一条导出命令随时生成和旧版一模一样的三个 CSV。
- 新旧快照可以混着比，命名规则保持兼容。

## 6. 分几步做（每步都独立可用）

| 阶段 | 做完你能得到什么 |
|---|---|
| **第一步** | 全部日常功能：采集（不含指纹）、各种查询、对比（含目录级汇总）、旧快照导入、CSV 导出。**做完这步，工具就全面超过旧版** |
| **第二步** | 指纹相关能力：按需全量/抽样内容校验、改名识别、HTML 报告、磁盘健康信息（SMART） |
| **第三步** | Linux / macOS 也能用；上千万文件规模的优化；跨快照历史趋势；供高级分析的数据导出 |
| **第四步（可选）** | 本地网页界面；重复文件专题报告 |

不存在"必须全部做完才有用"的依赖关系。

## 7. 需要你拍板的事

| # | 要决定的事 | 影响什么 | 推荐 |
|---|---|---|---|
| 1 | 只服务 Windows，还是将来也要在 Linux/macOS 用？ | 决定要不要做跨平台适配 | Windows 为主，跨平台放第三步 |
| 2 | 允许使用第三方小工具吗（如 smartctl）？ | 决定体检信息、指纹加速的取舍 | 核心零依赖；外部工具都做成"可选" |
| 3 | 指纹策略：平时不算、重要节点全量算？ | 决定"内容被改""改名搬家"能覆盖多少 | 日常不算；盘寄回 / 年检时全量算 |
| 4 | 需不需要"改名 / 搬家"识别？ | 依赖指纹覆盖度 | 需要就保证年检时全量指纹 |
| 5 | 查看方式：命令行 + HTML 报告够吗，还要网页界面吗？ | 决定第三步做不做 Web UI | 命令行 + 报告先行 |
| 6 | 未来规模：大概几块盘、每盘每年采几次、单盘最多多少文件？ | 决定性能设计目标 | 先按 20 块盘、每年 6 次、单盘千万文件设计 |
| 7 | 有没有"一块盘分多个区"的情况？ | 决定要不要做多分区支持 | 默认支持单分区，多分区做兜底 |
| 8 | 要不要记录文件权限明细（ACL）？ | 增加复杂度，用途有限 | 暂不记录，需要再加 |
| 9 | 快照文件要不要在盘上再存一份？ | 盘和"档案"同生共死，异地也带着清单 | 推荐存一份 |

回复编号和选择即可；默认选项都按"推荐"列执行也可以。

## 8. 名词小抄

- **CSV**：逗号分隔的纯文本表格。什么软件都能打开，但数据量大时基本没法查询。
- **快照**：某一天对整块盘做的一次完整记录。
- **SQLite**：Python 自带的小型数据库，整个库就是一个文件——可以理解成"单文件的档案柜"。
- **哈希 / 指纹**：由文件内容算出的一串字符。内容变则指纹变，用来验证"内容没被动过"。计算需要把文件完整读一遍。
- **SMART**：硬盘自带的健康数据（温度、通电时间、坏道计数等）。
- **全文索引**：像书末的关键词索引，让"按名字搜索"变快。
- **du**：disk usage 的缩写，统计目录占用的经典叫法。
- **返回码**：命令结束时给脚本的一个数字信号，用来判断"有没有差异、有没有出错"。
