# Windows 真机复验清单（2026-10-01）

> 用途：这一轮修了多处 Windows 专属问题（URI/路径、文件占用、控制台编码、Excel 乱码等），
> 其中一部分在 WSL 里没法真机判定。请按下面清单在你的 Windows 机器上过一遍，
> 有问题就把**截图 + 控制台报错 + 后端日志片段**发我。
>
> 包：`dist-packages/cold-manifest-0.2.0-win.zip`（解压即用，含 Windows 与 Linux 启动脚本）。

## 0. 准备
1. 解压到一个**新目录**（例如 `D:\cldm-test\`；路径含空格/中文/`..` 现在也都支持，但建议先用普通路径做首轮）。
2. 双击 `setup.cmd`（离线安装，无需联网）。
3. 双击 `start.cmd`；浏览器打开 `http://localhost:8765`。
   - 首次运行 Windows 防火墙可能弹窗（我们监听 0.0.0.0 是为了局域网访问）——允许即可。

- 概览/浏览/搜索/跳过项/导出/重复文件 逐 tab 打开，**控制台无红色报错**
- 任务页：跑一次采集 + 一次哈希，进度与「已完成」通知正常；点取消能停

- 设置页：数据根、导入根等展示正确

## 3. 已知边界（不算 bug）
- **mac 不支持**（按你的决定）。
- **不设鉴权**、局域网可访问：同网段任何设备都能打开页面，别放在不受信的网络上。
- **SMART 依赖第三方工具**：Windows 需要 smartmontools；USB 桥接盘可能需 `-d sat`（程序会自动重试一次）。
- **数据根放在 exFAT/FAT32（U 盘）**：catalog 会自动从 WAL 回退到 DELETE 日志模式（会有 warning 日志），功能正常但性能略低。
- **路径极长（>260 字符）**：需在 Windows 打开"长路径支持"（组策略/注册表）；程序会在检测到很深的根路径时给提示。
- **指纹档 ≠ 逐字节验证**：抽样指纹（首/中/尾各 64KB）"高度可能重复"，要作为删除依据请用「按内容」档。

| # | 步骤 | 期望结果 |
|---|---|---|
| 1 | **两块盘不再合并成一行**：两块同型号同容量盘分别接上采集（各采一个快照），然后打开磁盘页 | 磁盘列表出现**两行**（而不是被静默合并成一行）；每行「身份」列有徽标——序列号对得上的是绿色「已验证」，对不上/没读出的是黄色「未验证」或红色「身份冲突」，不再两块盘共用同一串序列号 |
| 2 | **读到别的盘有醒目告警**：磁盘详情点「现在读取 SMART」，在两块盘都在线时故意用 `CLDM_SMARTCTL_DEVICE` 指到另一块盘的设备串（或直接交换两块盘的 USB 口后重试） | 结果区出现红色告警：说明「读到的盘与目标盘序列号不一致」，并给建议（拔掉其它同型号盘再试，或用 `--serial` 显式区分）；而不是把另一块盘的 SMART 当成正常结果展示 |

| 4 | **盘号不再决定答案**：现场跑 `smartctl --scan-open -j`（或看页面「现在读取 SMART」错误详情里的 scan_info），记下设备顺序；然后换 USB 口/换顺序重新插盘再采集 | 页面展示的 `device_used` / `mapped_by` 跟着**序列号**走（serial_match），而不是跟着 `/dev/sdN` 的盘号走——同一块盘无论排在 sd 几，认出来的都是它 |

| 5 | **身份卡重新校验**：把该盘接好后进磁盘详情身份卡，点「重新校验」 | 返回三态之一：已接好 → verified（已验证）/ unverified（未验证，附原因）；盘拔掉 → not_attached（未接入）；验证通过时身份状态刷新为「已验证」 |
| 6 | **手动确认 / 撤销**：点「手动确认」（二次确认弹窗）→ 状态变已验证，并显示「手动确认 · 时间」；再点「撤销确认」 | 回到「未验证」，来源/时间更新；下次接上盘可用「重新校验」自动核对 |
| 7 | **未验证原因可见**：找一块未验证的盘，看磁盘列表「身份」列徽标悬停 / 详情身份卡 | 徽标旁有**具体原因**（如"盒 ID xxx + 容量 4TB 唯一定位到真盘序列号 yyy"之类的说明），不是干巴巴一个"未验证" |

## 12. UAT 修复复测点（2026-10 真机 UAT 后）

针对本轮真机 UAT 暴露问题（详见《升级方案-v0.3》「真机 UAT 问题与解决方案」）的复测点。准备：至少一块 USB 硬盘盒 + 一块**容量相同**的内置盘（复刻并列场景）；必测项为 1/2/3：

- [ ] **1. preflight 不再误拦**：接一块能透传真序列号的 USB 盒，采集对话框填路径等依赖检查完成 →「开始采集」**不**禁用，preflight 的 `smart_serial` 显示 ATA 直通真序列号（不是 null）、`requires_manual_serial=false`；对应的"依赖检查拦住 ⇔ 采集也会拦"不变量已被测试固化（`d977044`）
- [ ] **2. 快选显示真序列号**：采集对话框本机磁盘快选 → USB 盒行显示「真盘序列号」标（`serial_source="smartctl"`、`serial_verified=true`）；系统枚举值只作灰色标注「系统枚举：X（可能是盒子 ID）」，不再把 `20260123004775F` / `0123456789ABCDEF` 当序列号展示（`608bd40`）
- [ ] **3. 容量并列不读错盘**：让 USB 盒（2TB）与内置 2TB 盘**同时在线**，对盒内盘采集 → 快照登记到**盒内盘**名下（核对序列号与盘体标签一致，绝不出现"登记到内置盘"）；若候选并列无法区分，应明确报歧义而不是按扫描顺序猜（`8c25aaf`，本轮事故：P300 被登记到 WD SN570 名下）
- [ ] **4. 容量只作排除、不作认同**：找两块**同容量不同型号**的盘同时在线分别采集 → 各自身份校验通过、两行不合并、互不串号
- [ ] **5. 手填闸门（Windows 硬规则）**：用一个**不透传真序列号**的盒（或临时模拟 probe-only 形态）采集 → 前端要求手填盘体序列号才能开始；后端 400 / CLI rc=2；`smartctl_unverified`（读到了但没确认是目标盘）同样被拦，宁严勿松（`33134e1`）
- [ ] **6. 盘符不绑定**：采集完一块盘后**换另一块盘插同一个 USB 口/盘符**，等 15 秒以上再操作 → 页面按新盘身份显示（设备表 15s TTL 过期重扫），不会沿用上一块盘的缓存身份；立刻操作时旧缓存命中属预期（`8c25aaf`）
- [ ] **7. smartctl 不在 PATH 也能直读**：确认 Windows 宿主未把 smartctl 加入 PATH 的环境下（打包目录场景），采集对话框快选仍能带出 ATA 真序列号（可执行文件走统一解析 `smartctl_exec()`，不再写死 `smartctl`）（`608bd40`）
- [ ] **8. 删盘/卷免 F5**：磁盘页删除一个卷、再删除一块空盘 → 列表即时更新，无需手动刷新；开着卷详情面板删该卷 → 无 404 报错弹窗（`b507810`）
- [ ] **9. 现场读取 SMART 的身份核验**（`328932b` 已完成）：磁盘详情点「现在读取 SMART」→ 先枚举本机全部磁盘并按**盘符直读真序列号**核验：不在线 → 警示「这块盘现在不在线」（插上后重试）；序列号与记录不符（枚举到另一块）→ 警示「检测到另一块盘」并列出"记录/当前"两个序列号；真序列号不可得 → 警示「序列号未经核实」；整机枚举失败 → 警示「设备枚举失败」。四种情况**一律不读取**，绝不把别的盘的 SMART 当目标盘展示
- [ ] **10. 真实 smartctl 夹具回归**：WSL 直调宿主 `C:\Program Files\smartmontools\bin\smartctl.exe -i -j <盘符>`（NVMe 无需管理员），比对页面显示的型号/序列号/容量与真实输出一致（夹具口径见《升级方案-v0.3》「验证方法（教训）」与仓库根 `cldm-diag.txt`）
