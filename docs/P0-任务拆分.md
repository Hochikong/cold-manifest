# P0 任务拆分与执行方案

> 状态：待 review，未开工。依据 `升级方案-v0.3.md` §9 的 P0 范围；环境见 `开发环境与测试.md`。
> P0 目标：把现有 legacy 快照导入新存储，用**只读 Web + CLI** 完成浏览、查询、diff、导出，并达到设计文档的验收指标。

## 0. 总览

| 阶段 | 内容 | 关键出口（Gate） |
|---|---|---|
| **L0 骨架** | 后端包/CLI/服务壳 + 前端工程/代理 | G0：服务起、空壳页可达 |
| **L1 存储与导入** | catalog/snapshot DDL、import-legacy、seal、统计 | G1：样本对账一致 |
| **L2 只读 API 与 diff** | 查询端点、keyset 分页、diff 物化、导出 | G2：冒烟 + 性能达标 |
| **L3 前端页面** | 总览 / 浏览 / 搜索 / diff / 导出 | G3：页面可用、截图通过 |
| **L4 验收** | pytest + Playwright E2E + 性能 + v1 交叉验证 | G4：验收清单全绿 |

依赖关系：L0 →（L1 ∥ 前端脚手架）→ L2 → L3 → L4。**每个 Gate 通过后停下来给你看结果**，确认再进入下一阶段。

## 1. 仓库结构（P0 新增）

```
cold-manifest/
├── pyproject.toml            # 扩展：deps(fastapi/uvicorn/pydantic)、dev(pytest/httpx)、入口 cm
├── src/cold_manifest/        # 后端包
│   ├── cli.py                #   cm serve / import-legacy / diff / export
│   ├── server.py             #   FastAPI app、静态托管前端产物、/api/health
│   ├── db.py                 #   连接工具（snapshot 库只读 immutable / catalog WAL）
│   ├── schema.py             #   DDL：catalog.db / snapshot.db / diff 库
│   ├── catalog.py            #   盘 / 卷 / 快照注册与查询
│   ├── import_legacy.py      #   v1 三件套 → snapshot.db
│   ├── diff_engine.py        #   ATTACH join → diff 物化库
│   └── api/                  #   只读端点（snapshots/entries/tree/du/stats/search/skipped/diffs/export）
├── frontend/                 # React 18 + TS + Vite + AntD 5 + ECharts + TanStack Query
│   ├── src/api/              #   OpenAPI 生成客户端 + Query hooks
│   ├── src/pages/            #   页面（见 L3）
│   └── e2e/                  #   Playwright Test（L4）
├── tests/                    # pytest（导入对账、API、diff 分类）
└── data/                     # 运行数据（gitignore）：catalog.db、<volume_id>/<ts>/snapshot.db、_diffs/
```

约定：`.gitignore` 补 `data/`、`frontend/node_modules/`、`frontend/dist/`、`__pycache__/`、`.venv/`、`*.db`（仓库内）。样本数据**不拷贝**，导入时直接指向 `Legacy/backupStatus260505/...`。

## 2. 各工作线

### L0 骨架（0.5 天）
- 后端：填 `pyproject.toml`（`requires-python >=3.10`，依赖三件套 + dev 两件套）；`cm serve` 起 uvicorn（默认 `0.0.0.0:8765`）；`/api/health`；其余子命令先出壳（参数解析完整、逻辑抛 NotImplemented）。
- 前端：`npm create vite` React+TS；接 AntD/ECharts/TanStack Query；vite `server.host` + `/api` 代理到 8765；三条空壳路由（总览/快照/对比）。
- 验证 G0：`cm serve` + `npm run dev`，Windows 浏览器开 5173 见空壳；`/api/health` 200。
- 执行：fixer（后端脚手架、前端脚手架两个独立任务，可并行）。

### L1 存储与导入（1.5–2 天）
- `schema.py`：按设计 §5.1/5.2 落 DDL（entries/skipped/meta/dir_rollup；catalog 的 disks/volumes/snapshots/on_disk_copies/batches/diff_runs/tasks）。
- `import_legacy.py`：流式解析 metadata.csv/tree.csv/warnings.csv；DictReader 自适应动态 `level_N`；按路径前缀反建目录行（`dirs_source=derived`）；warnings 按 `(path, warning_type)` 去重；ISO mtime → ns；每 1–5 万行批量事务；结束执行 seal（建索引 + dir_rollup + `PRAGMA optimize`）。
- `catalog.py`：导入登记（disk/volume/snapshot/统计）。
- 验证 G1（对账基准）：
  - 样本 A（`X0DG6A2GS_P0`）：22 文件、8 个 warnings 去重为 4；
  - 样本 B（`X0FGBM2AS_P0`）：**2,981,921 文件、52,536 目录、1,874.4 GB（逻辑和）、深度直方图**与 v1 一致；
  - 重复导入幂等；1.13GB 导入耗时 <10min（实测记录）。
- 执行：fixer；对账脚本由我复核。

### L2 只读 API 与 diff（1.5–2 天）
- 端点（设计 §6.2 的 P0 子集）：`/api/snapshots`、`/api/snapshots/{sid}`、`/stats`、`/entries`、`/tree`、`/du`、`/search`（前缀模式）、`/skipped`；`POST/GET /api/diffs`、`/api/diffs/{id}/entries`；`/export`（`csv`、`v1_csv`）。
- 分页：keyset 游标（禁 OFFSET）；计数分层（快照预计算 / 目录直数 / 过滤列表仅 has_more）。
- `diff_engine.py`：ATTACH 两库 JOIN → 物化 `data/_diffs/<id>.db`；分类 `added/removed/size_changed/mtime_changed/type_changed/identical`；未启用哈希时 `content_changed/moved_or_renamed` 为 `null`；`(a,b,options_hash)` 幂等复用。
- CLI：`cm import-legacy`、`cm diff`（退出码 0/1/2）、`cm export --v1-layout`。
- 验证 G2：端点冒烟；性能实测——du/tree/stats <2s、diff 物化 <60s、结果翻页/过滤 <500ms（样本 B）。
- 执行：fixer（API）；diff 分类用例由我设计并复核。

### L3 前端页面（2–3 天）
- 先接数据：OpenAPI 生成 TS 客户端 + TanStack Query hooks（fixer）。
- 页面（designer 主导，按 UX 文档）：
  1. **总览**：盘/快照列表 + 快照时间线；
  2. **快照概览**：KPI + 扩展名分布 + 大小直方图 + 顶层目录 treemap；
  3. **目录浏览**：懒加载目录树 + 虚拟滚动表格 + 目录 rollup 信息头 + 面包屑；
  4. **搜索**：条件区 + 结果表 + 导出；
  5. **对比**：A/B 选择 + 差异 KPI + 目录汇总表 + 文件明细 + 详情抽屉；
  6. **导出抽屉**：CSV / v1_csv / HTML 简版报告（若排期紧，HTML 报告顺延 P1）。
- 大数据策略：keyset"加载更多" + 虚拟滚动 + 树懒加载（严禁一次性加载百万行）。
- 验证 G3：designer 用 playwright MCP 截图/交互冒烟；你在 Windows 浏览器 `localhost:5173` review；发现的问题走 designer 定点修复。
- 执行：designer（页面/交互/视觉）+ fixer（数据接线，边界由我切分避免冲突）。

### L4 验收（1 天）
- `tests/`：导入对账（G1 固化）、API、diff 分类（构造重命名/同尺寸改写用例标注证据等级）。
- `frontend/e2e/`：Playwright Test 全链路（导入 → 浏览 → 搜索 → diff → 导出），跑在样本数据上。
- 性能脚本：对照设计 §5.4 指标出数。
- 交叉验证：v2 `cm export --v1-layout` 产物 → 用 legacy `compare` 跑一遍 → 与 v2 diff 结果对账。
- 执行：fixer 写用例，我跑测并汇总验收报告给你。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| 3M 行导入内存/性能 | 流式 + 批量事务；先样本 A 后样本 B；G1 卡实测耗时 |
| 目录反建/rollup 正确性 | 以样本 B 的 52,536 目录数与深度直方图为固定基准对账 |
| 查询不达性能指标 | 索引/keyset 方案已定；G2 实测不达标则先调索引再报你 |
| 前端大表/树卡顿 | 虚拟滚动 + 加载更多；用真数据（非 mock）验证 |
| v1 行为差异（退出码、depth 语义） | 设计文档 §8 已列；交叉验证脚本覆盖 |
| designer/fixer 写冲突 | 页面与数据接线分离，文件级边界由我指定 |
